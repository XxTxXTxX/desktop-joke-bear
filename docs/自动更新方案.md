# 自动更新方案（0 成本 / 国内可用）

> 目标：你这边发版，她那边**启动时自动检测**，静默下载、校验、切换，下次启动生效；
> 出错能自动回滚，全程不打扰她使用。

## 1. 前提：Windows 不允许覆盖运行中的程序

正在运行的 `exe`/`.pyd` 被系统锁定，直接覆盖必然失败。所以只能在三种做法里选：

| 做法 | 说明 | 用户感受 |
|---|---|---|
| A 退出→替换→重启 | helper 进程换目录 | 熊消失 2–4 秒 |
| **B 下载到新目录 → 下次启动切换（推荐）** | 本次不生效，写 pending 标记 | 完全无感 |
| C 只更新素材/台词 | 热重载，不重启 | 完全无感 |

推荐：**B 为主（代码）+ C 兜底（台词、精灵、配色）**。

## 2. 目录分层（关键设计）

```
桌面宠物/
├─ runtime/              python-embed + Pillow     ← 很少变，只有全量安装才动
├─ app-1.4.2/            业务代码 + 素材（旧版本）
├─ app-1.4.3/            业务代码 + 素材（新版本）
├─ current.txt           内容：app-1.4.3            ← 切换只改这一个指针
├─ pending.txt           有值表示"下次启动切成哪个"
└─ launcher.exe          读 current.txt → 启动 runtime\pythonw.exe app-<v>\main.py
```

好处：

- 更新包只有几百 KB（`app/` 目录），不是 30MB 安装包；
- 回滚 = 改 `current.txt`，零风险；
- 素材/台词可以标成 hot，**不重启就生效**。

## 3. 更新源：Gitee Releases（0 成本）

| 选项 | 国内速度 | 成本 | 备注 |
|---|---|---|---|
| **Gitee Release 附件** | 快 | 0 | 公开仓库无需 token |
| GitHub Releases | 慢、偶发重置 | 0 | 作为备用 url |
| 对象存储 | 快 | 免费额度会到期 | 不推荐 |

`update.json`（同样放 Release 附件，客户端只读这个）：

```json
{
  "version": "1.4.3",
  "min_version": "1.3.0",
  "urls": [
    "https://gitee.com/USER/REPO/releases/download/v1.4.3/app-1.4.3.zip",
    "https://github.com/USER/REPO/releases/download/v1.4.3/app-1.4.3.zip"
  ],
  "sha256": "…",
  "size": 512000,
  "notes": "修了眼镜对齐；新增投喂",
  "mandatory": false,
  "broken": [],
  "sig": "ed25519:…"
}
```

`urls` 是数组 → 主源挂了自动换备用源，这是 0 成本方案最重要的容错。

## 4. 运行时序

```
launcher 启动
  └─ 若 pending.txt 存在 → 切 current.txt → 删除 pending.txt
       └─ 启动 app-<新版本>
            └─ 30 秒内没崩 → 清理旧版本目录
            └─ 30 秒内崩了 → 切回旧版本（记一条日志）

app 启动 3 秒后
  └─ GET update.json（失败静默，4 小时后再试）
       ├─ version <= 本地 → 结束
       └─ version >  本地 → 下载 → sha256 校验 → 签名校验
              ├─ 任一失败 → 删除临时文件，24 小时后再试
              └─ 成功     → 解压到 app-<ver>/ → 写 pending.txt
                            → 气泡提示："我换新版本了，下次开生效"
```

运行期间也可以每 6 小时查一次，但**任何情况下都不主动杀进程重启**。

## 5. 安全设计（更新通道 = 最高价值攻击面）

| 层 | 做法 | 防什么 |
|---|---|---|
| 传输 | HTTPS + `sha256` | 传输损坏、中间人改写 |
| 清单 | **Ed25519 签名**，公钥硬编码进 launcher | 仓库被改、托管方被攻破 |
| 版本 | `min_version` 强制升、`broken` 列表禁装 | 装到已知有问题的版本 |
| 运行 | 启动失败自动回滚 | 更新把程序搞坏 |

签名是 0 成本能拿到的最大收益：私钥只在你本地，**别人能改仓库也发不出能装的包**。

## 6. 发布流程（你这边一条命令）

```
python tools/release.py --ver 1.4.3 --notes "修了眼镜对齐"
  ├─ 打包 app/ → app-1.4.3.zip（~500KB）
  ├─ 算 sha256、生成 update.json、Ed25519 签名
  └─ 上传到 Gitee Release（token 存本地，不进仓库）
```

她那边：下次启动自动检测 → 下载 → 校验 → 切换。

## 7. 里程碑

| 阶段 | 内容 | 工作量 | 验收 |
|---|---|---|---|
| U0 | 三层目录 + version.json + launcher | 1 天 | 手动改 current.txt 能切版本 |
| U1 | 拉清单 + 下载 + 校验 + 提示 | 1 天 | 发新版本，她重启后收到提示 |
| U2 | 解压切换 + 重启 + 失败回滚 | 1 天 | 故意发坏包，能自动退回旧版 |
| U3 | tools/release.py 一键发版 | 1 天 | 一条命令完成发版 |
| U4 | Ed25519 签名校验 | 0.5 天 | 篡改清单后客户端拒绝 |
| U5 | 素材/台词热更新 | 0.5 天 | 改台词 5 秒后生效，不重启 |

必须做的是 U0–U2；U3 决定以后发版累不累；U4 建议做。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| Defender 误报打包 exe | 分层方案减少打包体积/加密段；安装说明写"添加排除"；代码签名要钱，0 成本接受偶发误报 |
| 她长期不关机 | 「运行满 7 天」时提示重启一次 |
| 下载中断 | 解压前校验 sha256，失败即删，绝不留半包 |
| 更新把功能搞坏 | 启动失败自动回滚 + `broken` 列表 |
| 正在用时被重启 | 永远只在启动时应用，不杀进程 |
| 提醒通道受影响 | 更新与消息通道正交（邮件照常） |
